# VIRA-1 — Database & RAG 아키텍처 (웹페이지 섹션용 요약)

> **섹션 ID:** `#database-rag`
> **네비게이션 라벨:** `Database & RAG` (국문: `데이터베이스 · RAG`)
> **섹션 헤드라인:** 검사 데이터를 자산으로, AI를 스스로 진화하는 시스템으로
> **서브 헤드라인:** VIRA-1은 픽셀 단위 결함 검출에서 끝나지 않습니다. 모든 판정 결과를 구조화해 축적하고, 이를 RAG 어시스턴트와 재학습 파이프라인의 연료로 사용합니다.

## PART 1. RAG 기반 지능형 품질·설비 어시스턴트 (Copilot)

VIRA-1의 비전 AI가 생산하는 수치 데이터와 현장의 텍스트 문서를 결합해, 자연어로 질문하고 답을 얻는 어시스턴트를 구성합니다.

### 1-1. 활용 시나리오

**① 실시간 설비 트러블슈팅 (Maintenance Assistant)**
- 질문 예시: *"측면 카메라에서 5px 이하 미세 크랙 미검이 잦은데, 과거 유사 사례의 조명 세팅은?"*
- 동작: 벡터 DB에 적재된 과거 작업 이력 · 조명 세팅 이력(로우앵글 다크필드 LED 바) · Siemens S7-1200 PLC 매뉴얼을 검색
- 결과: 최적 하드웨어 세팅 가이드를 즉시 제공 → **설비 다운타임 최소화**

**② 복합 품질 기준 질의응답 (Quality Standard Q&A)**
- 질문 예시: *"종횡비 5:1 이상 linear 결함 중 REVIEW 판정 케이스의 평균 면적은?"*
- 동작: 텍스트화된 품질 SOP(표준작업지침서) + 검사 DB 로그를 결합
- 결과: 답변과 통계를 동시에 생성 → **다차원 불량 트렌드 분석**

### 1-2. 파이프라인 구현 설계

| 단계 | 내용 |
|---|---|
| 지식 DB 구축 | 설비 매뉴얼(NVIDIA Jetson · 카메라 · 조명), 부품 규격서, 과거 불량 원인 분석 리포트를 Chunk 분할 → 벡터화 → 적재 |
| Log-to-Text | 검출 결과(면적 · 길이 · 스코어)를 자연어 문장으로 변환. 예: `"다이 #1045에서 0.65 스코어의 linear 스크래치 발견됨"` → 벡터 스토어에 지속 저장 |
| 검색·생성 | 자연어 질의 → 벡터 검색(문서 + 로그) → 근거 기반 답변 생성 |

## PART 2. 하이브리드 데이터베이스 아키텍처 (재학습 데이터 댐)

RAG를 도입하지 않는 경우, 클라우드를 **차세대 모델 학습용 '데이터 댐'** 으로 운용합니다. 설계 원칙은 **Human-in-the-Loop(HITL) 기반 고품질 라벨링 데이터 확보**입니다.

### 2-1. 3계층 스토리지 분리

| 계층 | 스택 | 역할 | 핵심 설계 |
|---|---|---|---|
| 오브젝트 스토리지 | **MinIO** | 원시 이미지 · 라벨 데이터 | 경로: `s3://vira1-data/raw/{lot_id}/{die_id}.jpg`<br>보존: NG · REVIEW 이미지 **2년 전체 보존**, OK 이미지 30일 후 **일 1% 샘플링**만 잔존 |
| 시계열 DB | **TimescaleDB** | 인프라 · 추론 지연 모니터링 | 인라인 검사 타이밍 텔레메트리(MQTT) 저장<br>촬상→판정 **P95 120ms**, 판정→배출 완료 **500ms** 구간별 기록 · Grafana 연동 |
| 관계형 DB | **PostgreSQL 16** | 메타데이터 · 재학습 데이터셋 구성 | 추론 결과 ↔ 작업자 최종 리뷰 매핑 (코어 DB) |

> 무거운 원본 이미지와 밀리초 단위 로그를 분리 저장해 **P95 120ms의 실시간성**을 보장합니다.

### 2-2. 재학습용 핵심 스키마

**Table 1 — `inspection_master` (검사 마스터)**

| 컬럼 | 설명 |
|---|---|
| `die_id` (PK) | 엔코더 기반 트래킹 ID |
| `image_path` | MinIO 내 이미지 저장 경로 |
| `ai_decision` | 모델 초기 판정 (OK / REVIEW / NG) |
| `human_decision` | 작업자 최종 합부 판정 (REVIEW 건의 수동 판정 결과) |
| `is_used_for_training` | 재학습 데이터셋(2,000~4,000장, Train/Val/Test 분할) 포함 여부 플래그 |

**Table 2 — `defect_polygons` (세그멘테이션 결함)**

| 컬럼 | 설명 |
|---|---|
| `polygon_id` (PK) | 폴리곤 식별자 |
| `die_id` (FK) | 검사 마스터 참조 |
| `defect_class` | `linear`(스크래치/크랙) · `blob`(파티클/치핑) · `area`(변색/얼룩) |
| `polygon_points` | JSON 폴리곤 외곽선 좌표 배열 (채움비 100% 정보 보존) |
| `pixel_area` | 픽셀 면적 산출값 |
| `confidence_score` | 모델 예측 신뢰도 |

### 2-3. 이 구조가 만드는 가치

**① Active Learning 선순환**
스코어 **0.35~0.70**의 REVIEW 구간은 모델이 가장 헷갈려 하는 엣지 케이스입니다.
`ai_decision = 'REVIEW' AND human_decision != ai_decision` 조건으로 쿼리하면, 모델 약점을 가장 빠르게 보완하는 **최상급 라벨링 데이터셋이 즉시 완성**됩니다.

**② 물리적 증강(Augmentation) 재료 확보**
희소 클래스 대응 시, `defect_polygons`의 픽셀 정보를 마스크로 활용한 **copy_paste 증강**으로 완벽한 합성 데이터를 무한 생성합니다.

**③ 3분기 판정의 데이터화**
OK / NG 뿐 아니라 인간 개입이 필요한 **REVIEW** 상태를 별도 DB화 → 작업자 교정 판정을 축적해 YOLO26s-seg 모델을 현장에 맞게 진화시키는 파인튜닝 재료로 활용.

## 웹페이지 노출용 핵심 지표 (카드/배지 소재)

| 지표 | 값 |
|---|---|
| 판정 지연 (P95) | `120ms` |
| 판정 → 배출 완료 | `500ms` |
| REVIEW 스코어 구간 | `0.35 ~ 0.70` |
| 재학습 데이터셋 규모 | `2,000 ~ 4,000장` |
| NG · REVIEW 이미지 보존 | `2년` |
| OK 이미지 정책 | `30일 후 일 1% 샘플링` |
| 폴리곤 정보 보존 | `채움비 100%` |
