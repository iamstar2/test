## 왜 YOLO26-seg인가 — 버전 비교

세그멘테이션이 필요하다는 결론(AABB 채움비 6.8% → 박스 기반 detect는 부적합, 원본 리포트 2장)은 확정이지만, **YOLO 계열 중 어느 세대를 쓸지는 별도로 근거가 필요하다.** 실전 사례가 가장 많은 YOLOv8-seg, 그 다음 세대인 YOLOv11-seg, 그리고 최신 세대인 YOLO26-seg 세 가지를 이 프로젝트의 실제 제약(박형 결함 검출, Colab 세션 시간, 최종 엣지 배치 지연)에 대해 비교했다.

| 기준 | YOLOv8-seg | YOLOv11-seg | **YOLO26-seg (채택)** |
|---|---|---|---|
| 성숙도 | 2023 출시, 커뮤니티·레퍼런스 최다 | 2024 출시, v8 대비 효율 개선(C3k2, C2PSA) | 2025 출시 — **실전 검증 사례 적음 (리스크)** |
| 후처리 | NMS 필요 | NMS 필요 | **NMS-free, end-to-end** |
| 소형·박형 객체 대응 | 표준 DFL 박스 회귀 | DFL + 부분 어텐션(C2PSA), 표준적 개선 | **DFL 제거 + ProgLoss/STAL로 소형 타깃 라벨 할당 강화** |
| 옵티마이저 | SGD / AdamW | SGD / AdamW | **MuSGD (Muon+SGD 하이브리드)** — 공식 발표 기준 수렴 안정성 개선 |
| 엣지 CPU 추론 속도 | 기준 | 기준 대비 소폭 개선 | **공식 발표 기준 최대 43% 단축** (자체 실측으로 재확인 필요) |
| Ultralytics -seg 헤드 성숙도 | 최고 | 높음 | 높음 (v8/v11 seg 헤드 계승, 신규 세대 리스크는 백본·헤드가 아니라 학습 스케줄러 쪽) |
| 이 프로젝트에서의 역할 | 실패 시 최종 대조군 | **1차 대조군** (freeze 스윕에서 YOLO26이 불안정하면 즉시 대체) | 채택 |

### 결정적 근거 3가지

1. **박형 결함 검출력이 태스크의 핵심 요구다.** 원본 리포트 2장의 `mask_ratio` 분석대로, 기본 다운샘플에서 5px 크랙이 1.25px로 소실된다. YOLO26의 ProgLoss/STAL은 정확히 이 소형·저신호 타깃의 라벨 할당·손실 가중을 강화하도록 설계되어, 다른 조건이 같다면 이 데이터의 실패 모드(얇은 크랙 소실)를 가장 직접적으로 겨냥한다.
2. **판정 지연의 결정성이 배포 요건이다.** VIRA-1 PRD의 추론 지연 목표(P95 ≤120ms, 판정→배출 ≤500ms)는 후처리 단계까지 포함한 예측 가능한 지연을 요구한다. NMS는 검출 개수에 따라 지연이 흔들리는 비결정적 단계인 반면, YOLO26의 NMS-free 구조는 이 변동성을 구조적으로 제거한다.
3. **최종 배치가 엣지다.** 학습은 Colab GPU에서 하지만 실제 서비스 대상은 Jetson급 엣지 디바이스(PRD 기술 스택 참조)다. YOLO26은 엣지·저전력 환경을 명시적 설계 목표로 삼고 있어, 학습-배치 간 성능 격차가 이전 세대보다 작을 것으로 기대된다.

### 고려했지만 제외한 대안

- **YOLOE (open-vocabulary, 텍스트/시각 프롬프트)** — 라벨링 없이 신규 결함 유형을 즉시 시도해볼 수 있다는 장점은 크지만, CLIP 텍스트 인코더가 약 600MB로 무겁고, 이 프로젝트는 이미 폴리곤 라벨을 보유한 **고정된 소수 클래스(3종: linear/blob/area)** 문제라 open-vocab의 유연성이 필요 없다. 미세 결함 경계 정밀도도 태스크 전용 파인튜닝 대비 불리할 가능성이 높다. → 지금은 배제하되, **라벨 없는 신규 결함 후보를 빠르게 스카우팅하는 보조 도구**로는 재검토 가치가 있다(`test_yoloe.py` 참고).
- **RT-DETR** — 트랜스포머 기반으로 정확도 상한이 높지만, 1,000장 규모의 소데이터 + Colab 세션 시간 예산 안에서는 수렴에 필요한 에폭·데이터가 더 크고, Ultralytics 내 `-seg` 지원 성숙도도 YOLO 계열보다 낮다. → 데이터가 수천~수만 장으로 늘어나는 시점에 재검토.

### 리스크와 완화

YOLO26은 출시 초기라 커뮤니티 검증 사례가 적다는 리스크가 있다. 이를 새 리스크로 남기지 않고, 원본 리포트의 실험 계획(freeze 3종 스윕)에 그대로 흡수했다: **`yolo26n-seg`로 파이프라인부터 검증 → `yolo26s-seg`로 확장하는 사다리를 유지하고, freeze 스윕에서 학습 불안정성이 보이면 동일 조건으로 `YOLOv11-seg`를 대조군으로 재실행**해 버전 선택 자체를 검증한다. 별도 실험 단계를 추가하지 않고 기존 "모델 크기 비교" 단계를 이 목적에도 활용한다.

## 데이터 실측 핵심 (근거의 출발점)

- **AABB 결함 채움비 6.8%** — 축정렬 박스는 93%가 빈 공간 → detect 대신 `-seg` 확정
- **축정렬 엣지 63.7%, 결함 실측 121.7°** — "대각 = 결함, 축정렬 = 정상 패턴"이 가장 강력한 판별 단서 → `mosaic=0`, `degrees=0`, `copy_paste=0.3`로 이어짐
- **라벨 번인 (최우선 위험)** — 라벨링 이미지 중 하나에서 노란 외곽선 픽셀 0.75% 검출. 이 상태로 학습하면 모델이 "노란 선"을 배운다 — 학습 전 자동 검사 필수

## 확정 설정 스냅샷

| 항목 | 값 |
|---|---|
| 모델 | `yolo26s-seg.pt` (전이학습, 스크래치 금지) |
| imgsz | 832 (원본 811px 기준 상한, 그 이상은 순수 업스케일) |
| mask_ratio | T4=2, L4·A100=1 (GPU 자동 분기) |
| batch | 16 / 24 / 40 (GPU 등급별, `batch=-1`로 1회 실측 권장) |
| optimizer | `AdamW`, lr0=0.001, lrf=0.01 (`auto` 금지 — GPU 바뀌면 조용히 SGD로 전환됨) |
| freeze | 10 (3종 스윕 `10 / None / 23` 후 확정) |
| epochs / patience | 200 / 25 |
| 증강 | `mosaic=0.0`, `degrees=0.0`, `copy_paste=0.3`, `hsv_h=0.0` |
| 클래스 | 5종 대신 형태 기반 3클래스(`linear`/`blob`/`area`)로 재편 |

## Colab 운영 요약

무료 T4 기준 **세션 3개, 총 약 14시간** (Pro L4면 절반). Drive 직접 읽기는 매 에폭 병목이므로 zip으로 압축해 `/content`에 스테이징하고, `project`는 Drive 경로로 지정해 세션 끊김에 대비한다.

## 평가 기준

주 지표는 마스크 mAP50이 아니라 **이미지 단위 미검율**. `conf=0.001, iou=0.7`로 검증 후 Mask PR 곡선에서 Recall 우선 지점을 골라 통과/사람 재검(VRS)/불량 확정의 3-way 임계값을 설계한다. 미검 0%는 통계적으로 검증 불가능하므로 목표로 삼지 않는다.

## 확정을 위해 아직 필요한 정보

원본 다이 이미지의 실제 해상도, Colab 등급(무료/Pro/Pro+), 인라인 카메라의 Mono/컬러 여부, 조명 방식, 유형별 인스턴스 개수, 가장 얇은 결함 폭(px), 합부 판정 스펙 — 총 7가지. 세부는 원본 리포트 11장 참고.
