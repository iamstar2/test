쟁점 1. 광학 분해능 — 전처리 영역이 아닙니다

계산이 맞습니다. 그리고 샘플링보다 회절이 먼저 걸립니다.

센서 화소 3.45µm 가정 시 배율 M ≈ 1.41x, 이 급 텔레센트릭 렌즈의 물체측 NA는 대략 0.08입니다. 회절 한계는 0.61λ/NA = 0.61×0.55/0.08 ≈ 4.2µm. 즉 5µm 목표는 광학계 자체의 분해 한계에 걸쳐 있고, 그 위에 2px 샘플링이 얹힌 상태입니다. (추정 — 실제 렌즈 NA·화소피치 확인 필요)

여기서 반드시 구분해야 할 게 있습니다.

검출(Detection)은 가능할 수 있습니다. 다크필드는 산란 신호를 봅니다. 분해되지 않는 입자도 배경 대비 밝은 점으로 나타납니다(KLA급 장비가 회절한계 훨씬 아래의 나노입자를 잡는 원리). 따라서 파티클·스크래치는 2px에서도 신호가 존재할 가능성이 있습니다.

측정(Sizing)과 형상 판별은 불가능합니다. Micro Chipping은 "결손 형상이 스펙 내인가"를 봐야 하는데, 이건 3~5px 이상 있어야 합니다. 현재 조건에서 5µm 치핑과 12µm 치핑을 구분할 방법이 없습니다.

조치 (모델 작업 착수 전 필수)

인증 표준 시료로 능력 검증 — PSL 표준구(3/5/10µm)와 라인폭 표준 레티클 촬영 후 MTF 및 SNR 실측
이미 확보한 SEM 교차검증 불량 500장에 대해, 각 결함 위치의 픽셀 SNR을 계산. SNR < 3인 결함의 비율 = 이 광학계의 구조적 미검 하한입니다. 이 숫자를 모르는 상태로 "미검 0%"를 약속하면 안 됩니다.
개선안: 5µm에 3px 확보 → 1.67µm/px → FOV 6.84mm → 10mm 다이에 2×2 타일 촬영. 데이터 4배, 시간 4배 → 100ms 택트와 충돌. 결국 택트 완화 / 스펙 완화 / 장비 증설 중 택일이며, 이건 경영 판단 영역입니다.
쟁점 2. 연산 예산 — 전처리는 되는데 추론 구조가 안 됩니다

전송은 생각보다 문제가 아닙니다. 문제는 추론입니다.

3×3 conv (32→32ch)를 16.78Mpx에 한 번 돌리면 309 GFLOP, 3장이면 928 GFLOP. A6000 FP16 실효 60 TFLOPS 기준 한 개 층에 15.5ms입니다. 풀해상도 U-Net은 두 자릿수 배로 초과합니다. 리사이즈는 금지 조건이므로 남는 길은 하나입니다.

쟁점 3. Mono로 패드 산화를 볼 수 있는가

컬러 카메라로 바꾸는 건 잘못된 처방입니다. Bayer 디모자이킹은 유효 분해능을 사실상 절반으로 떨어뜨립니다. 이미 2px인 상황에서 이건 자살행위입니다.

Mono가 불리한 이유는 센서가 아니라 광원입니다. 산화막은 박막간섭으로 특정 파장대의 반사율을 올리고 다른 대역은 내립니다. 광대역 백색 조명 + Mono 센서는 그 변화를 파장 축으로 적분해버려서 서로 상쇄되어 ΔGV가 0에 가까워질 수 있습니다.

해법: 협대역 순차 조명 (Mono 유지)

450 / 525 / 630nm LED를 순차 점등, 같은 Mono 카메라로 3장 취득 → 유사 멀티스펙트럼
산화막 두께에 대해 대비가 최대인 파장 1개만 골라 상시 운용하면 추가 시간 0
패드는 고정 위치이므로 산화 검사는 패드 ROI만 대상 → 전체 면적의 수 % 수준, 연산 부담 없음

사전 확인 실험 — 확보한 산화 불량 샘플에서 패드 영역 평균 GV와 정상 패드 평균 GV의 차이를 재고, 그 값을 패드 영역 노이즈 σ로 나눠보세요. ΔGV/σ < 3이면 현재 조명으로는 검출 불가이며 협대역 도입이 확정입니다.

쟁점 4. 양품 데이터 정책

H-5(양품 자동 삭제)와 F-1(양품 10만장)이 공존한다면, 10만장은 일회성 수집분일 가능성이 큽니다. 그렇다면 G-2(블레이드 주 단위 교체)에 대응할 방법이 없습니다. 정상 분포 자체가 주 단위로 움직이는데, 정상 데이터를 못 모으면 모델은 매주 낡아갑니다.

또한 F-2 체크는 정정이 필요합니다. 100,000:500 = 200:1이지 1000:1이 아닙니다. 이 차이는 전략 선택에 영향을 줍니다(200:1은 지도학습이 완전히 배제되지는 않는 구간).

쟁점 5. 미검 0.0%의 재정의

0%는 측정할 수 없습니다. 불량 500개로 검증해서 미검 0건이 나와도, 95% 신뢰 상한은 Rule of Three로 3/500 = 0.6% (6,000 DPPM) 입니다. 100 DPPM을 95% 신뢰로 입증하려면 불량 샘플 30,000개가 필요합니다. 물리적으로 불가능합니다.

재정의안

모집단 한정: "≥5µm, SNR≥3인 결함군"에 대한 미검률로 스펙을 좁힙니다. 쟁점 1의 SNR 조사 결과가 이 경계를 정합니다.
3-way 판정 (필수)
score < T_low        → 양품 통과
T_low ≤ score < T_high → 판정보류 → VRS
score ≥ T_high        → 불량 확정 배출
T_low는 검증셋 불량 최소 score에서 마진을 뺀 값으로 고정 (재현율 100% 지점 아래)
과검 2% 예산은 "VRS 이송률 + 오배출률"의 합입니다. 예: 오배출 0.5% + 보류 1.5%. 즉 미검 위험과 VRS 부하는 하나의 저울이며, 이걸 운영곡선(T_low를 움직이며 그린 escape–VRS load 곡선)으로 만들어 현장과 합의해야 합니다.
Conformal Prediction (split-conformal) 적용을 권합니다. 분포 가정 없이 "보류 구간이 실제 불량을 놓칠 확률 ≤ α"를 통계적으로 보증하는 구조라, 이 라인의 요구와 정확히 맞습니다.

세 가지 시점 확정

12bit → float 정규화: [2]에서 float32 진입, [5]에서 스케일 정규화. 8bit 변환은 하지 않는 것이 맞습니다. 12bit에서 ΔGV 10~20 LSB인 저대비 결함이 8bit에서는 0~1 LSB가 됩니다. 양자화가 결함을 삭제합니다.
테이프 배경 마스킹: [4], 즉 정렬 이후. 정렬 전에는 마스크 좌표가 맞지 않습니다. 그리고 경계는 마스킹하지 않고 edge zone으로 분리합니다 — 치핑이 사는 곳을 지워버리면 안 되니까요. 현장에서 "배경 마스킹이 핵심"이라고 본 판단은 방향은 맞지만, 지우기가 아니라 구획하기로 바꿔야 합니다.
정반사 마스킹: [4], CAD/티칭 레이아웃 좌표 기준. 이미지별 밝기 임계값으로 만들면 밝은 결함 자체가 마스킹되어 미검이 됩니다. 포화 화소는 "정보 없음" 플래그 채널로 모델에 넘기고, 값을 0으로 채우지 마세요 ("어두움"과 구분 불가해집니다).

D2D 차분을 강조하고 싶습니다. 현장에서 지적한 과검 원인이 "회로 패턴의 정상 반사와 범프 형태 미세차"인데, 이건 전부 인접 다이에서 동일하게 재현되는 결정론적 신호입니다. 룰베이스가 이걸 못 잡은 건 단일 이미지 임계값으로 봤기 때문이고, 비교 기준을 바꾸는 것만으로 과검의 상당 부분이 알고리즘 이전 단계에서 사라집니다.

5. 불균형 및 분할 전략
5-1. 아키텍처: 하이브리드 캐스케이드

지도학습 세그멘테이션 단독은 결함 500장으로 불가능하고, PatchCore 등 순수 이상탐지 단독은 16.78Mpx 메모리뱅크가 감당이 안 됩니다. 연산 예산 분석(쟁점 2)과도 맞물려 캐스케이드가 필연입니다.

Stage-1  D2D 차분 + zone별 임계        [풀해상도, 고전, 재현율 최우선]
   └─ 필요 시 EfficientAD를 보조 정상성 모델로 병행 (ms급 지연)
        ↓ 후보 좌표 (통상 다이당 수십 개)
Stage-2  패치 분류/세그멘테이션        [지도학습, 과검 억제 담당]
        ↓
3-way 판정 (Pass / Review / Reject)

핵심 인사이트 하나만 강조하겠습니다. 이 프로젝트의 진짜 자산은 결함 500장이 아니라, 기존 룰베이스가 뱉어낸 과검 5~7%와 그에 대한 VRS 현미경 재판정 기록입니다. 이건 "결함처럼 보이지만 정상인 것"에 대한 수만 건의 라벨된 하드 네거티브입니다. Stage-2가 배워야 할 게 정확히 이겁니다.

VRS 기록에서 "오배출 확정" 건의 이미지·좌표를 확보할 수 있는지가 이 프로젝트 성패의 절반입니다. 있다면 문제 난이도가 크게 내려가고, 없다면 도입 초기 3~4주간 룰베이스와 병행 운전하며 수집해야 합니다.

5-2. 희소 클래스 (크랙 12장)
5-클래스 분류기를 만들지 마세요. Stage-2는 binary(결함/정상)로 가고, 유형 분류는 리포팅용 보조 헤드로 분리
크랙은 스크래치와 "선형 결함"으로 통합 — 형태·광학 특성·필요 전처리가 동일
12장은 실제 크롭 기반 Copy-Paste 합성 (가법 합성으로 국소 대비만 이식, 배경 밝기 보존). GAN/디퓨전 생성은 배제 — 12장으로 학습한 생성모델은 결함의 광학 특성이 아니라 그 12장의 배경을 외웁니다
크랙 12장을 val/test 클래스로 쓰지 마세요. 12개로는 어떤 비율도 측정 불가입니다. 전량을 **"민감도 프로브 셋"**으로 따로 두고 비율이 아닌 검출 개수(예: 12/12)만 보고하세요

6. 리스크 시나리오
R1. 정렬 실패 → 과검 폭증

D2D 차분은 정렬 정밀도에 전적으로 의존합니다. 잔차가 0.5px만 넘어도 모든 에지에서 차분 아티팩트가 발생하고, 과검이 두 자릿수로 뜁니다. 미세 스테이지 진동(E-4)이 실재하므로 현실적인 위험입니다.

검증: 양품 10,000장으로 정렬 잔차 분포 측정. 요구: p99.9 < 0.3px
지표: 잔차 px, 그리고 잔차 vs 후보 개수의 상관계수 (상관이 보이면 아티팩트 발생 중)
완화: 잔차 임계 초과 다이는 D2D 경로를 우회해 정상성 모델 단독 판정 → 결과는 무조건 Review로
R2. 블레이드 마모 드리프트

절단면·치핑 형상이 주 단위로 변합니다. 신품 블레이드 데이터로 학습하면 마모 말기에 정상 절단면을 결함으로 봅니다(또는 그 반대).

검증: 배포 전, 블레이드 1사이클 전체 데이터를 오프라인 통과시켜 cut count 대비 anomaly score 평균의 추이를 그릴 것. 우상향 추세가 보이면 재학습 없이는 운용 불가
지표: 교대별 후보 개수 평균, score 분포의 PSI, 임베딩 PCA 상위성분의 KS 통계량
트리거: KS p<0.01이 3교대 연속 → 재학습 / score 스케일만 이동 → 임계값 자동 재보정 / 골든다이 재촬영값 이상 → 설비 점검 (모델 문제 아님)
R3. 광학적으로 신호가 없는 결함 (가장 위험)

라벨은 SEM 교차검증이라 정확한데, 이미지에 신호가 없으면 모델은 영원히 못 배웁니다. 더 나쁜 건 검증셋에서도 안 드러난다는 점입니다 — 학습·검증 양쪽에서 똑같이 안 보이니까요.

검증: SEM 확정 불량 500건 각각에 대해 라벨 마스크 영역의 픽셀 SNR을 계산. SNR < 3인 비율이 곧 미검 하한
지표: SNR 히스토그램, 결함 유형별·크기별 분해
이 측정은 모델 학습보다 먼저 해야 합니다. 결과에 따라 프로젝트 스펙 자체를 재협상해야 할 수 있습니다

상시 모니터링 로그 (다이당)
embedding(512-d) / anomaly_score / 후보수 / median·MAD / 정렬잔차 / blade_cut / lot_id / wafer_xy — 하루 36MB로 전수 드리프트 감시가 가능합니다.
