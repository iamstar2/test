[역할]
너는 반도체 후공정(Packaging/Dicing) 머신비전 및 딥러닝 데이터 파이프라인 설계 전문가야.
특히 극심한 클래스 불균형 하의 이상탐지(Anomaly Detection)와,
실시간 제약이 있는 GPU 전처리 최적화에 정통해.

[프로젝트 개요]
- 라인: PKG-A 다이싱 라인 (12인치 웨이퍼 절단 칩, Bare Die)
- 목표: 룰베이스 비전을 AI로 대체하여
  · 미검(Escape) 0% 유지
  · 과검(Overkill) 현재 5~7% → 2% 이하로 감축
- 현재 병목: 과검분 전량을 작업자가 현미경(VRS) 재확인 → 인건비·처리량 병목

---
[현장 조사 결과 - 실측]

■ A. 대상물
- 10mm × 10mm Bare Die, 완전 평면(2D)
- 표면: 유광 금속 경면 (실리콘 + 메탈 패드/솔더 범프)
- 로트별 미세 색차 有 (산화막 두께 차 → 간섭색, 웨이퍼 중심/외곽 편차)
- 품종 2~5종
- 최소 검출 불량 크기: 5µm (0.005mm)

■ B. 불량 유형
- 선형: 스크래치, 크랙(미세 표면 크랙)
- 면적: 이물(Particle), 색상 이상(패드 산화)
- 형상: 치핑(Micro Chipping) — 칩 모서리 집중
- 대비: **매우 낮음** (각도 바꿔야 보이는 수준)
- 정상 산포: 회로 패턴 밀집도에 따른 반사율 차이 有

■ C. 촬영계
- Area Scan 3대 (상면 1 + 측면 2), Global Shutter
- 4096 × 4096 px, **흑백(Mono), 12bit**
- 무손실 BMP/PNG 저장

■ D. 조명
- 링(Darkfield) + 동축(Brightfield) 병용
- 클린룸 설비 내부, 외광 완전 차폐 / 시간대 밝기 변동 없음
- LED 컨트롤러 피드백 제어로 광량 관리
- **정반사 항상 발생: 메탈 패드 및 솔더 범프 영역 (고정 위치)**

■ E. 물리 환경
- Stop & Go 정지 촬영, 위치 정밀도 ±0.05mm
- 배경: 다이싱 테이프(단색)
- 미세 스테이지 진동 有 / 실리콘 분진 有
- **택트 타임 100 ms/개**

■ F. 데이터
- 양품 100,000장 / 불량 500장
- 최소 클래스: 미세 표면 크랙 12장
- 라벨: **픽셀 마스크(Segmentation)**, 전자현미경 교차검증 기반 → 신뢰도 높음
- 메타데이터: 촬영시각, 라인/설비번호, 로트번호, **웨이퍼맵 X·Y 좌표**
- 수집 기간 1개월 이상

■ G. 드리프트
- 증착 공정 편차 → 칩 표면 반사율 미세 변동
- **다이싱 블레이드 주 단위 마모/교체 → 절단면·치핑 형상 변화**
- 항온항습 → 계절 영향 없음

■ H. 운영 제약
- 서버급 GPU Vision PC
- **판정 요구 시간 < 50ms** (전처리 + 추론 + 후처리 전부 포함)
- 미검 0.0% / 과검 2.0% 이하
- 기존 룰베이스 임계값 참조 가능
- **이미지 저장 정책: 불량만 저장, 양품은 용량 문제로 자동 삭제**

■ J. 현장 코멘트
- 기존 룰베이스 과검 원인 = 회로 패턴의 정상 반사, 범프 형태 미세차를
  스크래치/이물로 오판
- Micro Chipping이 다이싱 테이프 질감과 혼동됨
  → 배경 마스킹이 핵심일 것으로 현장 판단

(첨부: 양품 원본 / 불량 유형별 대표 / 최악조건(반사·블러) /
 판정 경계 사례 / 빈 다이싱 테이프 이미지)

[반드시 먼저 다뤄야 할 쟁점 - 내가 계산·검증한 모순들]

★쟁점 1. 광학 분해능이 물리적으로 부족할 가능성
  10mm ÷ 4096px = 2.44 µm/px (FOV에 여유 두면 ~2.9 µm/px).
  검출 목표 5µm은 약 **1.7~2.0 px**에 불과함.
  → Nyquist 관점에서 3~5px 확보가 정석인데 미달.
  → 전처리로 해결 가능한 문제인지, 광학계(렌즈 배율/FOV 분할 스캔)
     변경이 선행되어야 하는지 명확히 판단해줘.
     전처리로 못 고치는 영역이면 솔직히 그렇게 말해줘.

★쟁점 2. 연산 예산이 실제로 맞는지
  4096×4096 × 12bit(16bit 컨테이너) = 약 33.5 MB/장
  × 3대 = 약 100 MB/제품, 이걸 50ms 안에 처리 → 실효 2 GB/s 이상 필요.
  → CPU-GPU 전송(H2D)만으로 예산을 잡아먹는지,
     전처리를 어디까지 GPU(CUDA/DALI/CV-CUDA)로 밀어야 하는지,
     혹은 카메라단 FPGA/ROI 크롭으로 데이터를 미리 줄여야 하는지
     ms 단위 예산표로 나눠줘.

★쟁점 3. 흑백 카메라로 "색상 이상(패드 산화)"을 검출할 수 있는가
  B-1에는 색상 이상이 불량으로 잡혀 있는데 C-2는 Mono임.
  → Mono 조건에서 산화가 반사율 변화로 충분히 드러나는지,
     아니면 이 항목만 별도 컬러 카메라/멀티스펙트럼이 필요한지 판단해줘.

★쟁점 4. 데이터 정책과 보유량의 모순
  H-5는 "양품 자동 삭제"인데 F-1은 양품 10만 장 보유임.
  → 이 10만 장이 일회성 수집분이라면, 드리프트(블레이드 주 교체) 대응을
     위한 지속적 정상 데이터 확보 정책을 어떻게 설계해야 하는지 포함해줘.
  (참고: F-2에 1000:1로 체크했으나 실제 비율은 200:1임)

★쟁점 5. 미검 0.0%는 통계적으로 보장 불가능한 목표임
  → "0%"를 어떤 지표·신뢰구간으로 재정의해야 현실적인지,
     그리고 불확실 구간을 VRS로 넘기는 3-way 판정(양품/불량/판정보류)
     구조가 타당한지 의견을 줘.

[요청 사항]

1. **전처리 순서도**
   원본 12bit 이미지 입력부터 모델 입력 텐서까지 단계를 번호로 나열하고,
   각 단계가 왜 그 순서에 와야 하는지 근거를 적어줘.
   특히 아래 3가지는 순서를 명시적으로 확정해줘.
   - 12bit → float 정규화 시점 (8bit 변환은 하지 않는 전제가 맞는지 포함)
   - 다이싱 테이프 배경 마스킹 시점
   - 정반사(패드·범프) 포화 영역 마스킹 시점
   순서를 바꾸면 안 되는 구간과 그 이유를 별도로 표시해줘.

2. **기법별 상세**
   각 단계마다
   - 기법명 (라이브러리/함수 수준까지: OpenCV, CUDA, DALI, Albumentations 등)
   - 권장 파라미터 초기값 + 그 숫자가 나온 근거
   - 이 현장 조건(경면·저대비·5µm·50ms)에서 그 기법을 고른 이유

3. **학습 전용 / 추론 공통 구분**
   증강, 정규화, 마스킹, 크롭 각각을 Train-only / Inference-shared로
   반드시 라벨링해서 표로 정리해줘.
   (특히 정규화 통계값을 어느 범위에서 산출할지 — 전체/로트별/웨이퍼별)

4. **배제할 기법**
   일반적으로는 쓰지만 이 라인에서는 쓰면 안 되는 전처리와 이유.
   최소한 아래는 판단을 명시해줘.
   - Gaussian Blur / Denoising (5µm 결함 소실 위험)
   - 전역 CLAHE (회로 패턴 반사율 차를 결함으로 증폭할 위험)
   - Resize / Downscale
   - 회전·플립 증강 (웨이퍼 방향성·다이싱 방향성 관점에서)
   - JPEG 계열 어떤 손실 압축이든

5. **불균형 및 데이터 분할 전략**
   - 200:1 불균형 하에서 Supervised Segmentation이 맞는지,
     양품 10만 장을 활용한 Anomaly Detection
     (PatchCore / PaDiM / Reverse Distillation 등)이 맞는지,
     아니면 하이브리드(1차 이상탐지 → 2차 분류)인지 근거와 함께 추천해줘.
   - 크랙 12장 같은 희소 클래스 처리 방안.
   - Train/Val/Test 분할 기준: **웨이퍼맵 X·Y 좌표와 로트번호를 활용해
     데이터 누수를 막는 방법**을 구체적으로.
     (같은 웨이퍼의 인접 다이는 거의 중복 데이터라는 점을 반드시 반영)
   - 블레이드 교체 주기를 분할에 어떻게 반영할지.

6. **리스크 시나리오**
   이 파이프라인이 현장에서 실패할 수 있는 경우 3가지와,
   각각을 양산 투입 전에 검증할 구체적 방법(측정 지표 포함).
   블레이드 마모에 따른 드리프트 감지·재학습 트리거 설계도 포함해줘.

7. **구현 코드**
   최종 파이프라인을 실행 가능한 Python 코드로.
   - 전처리: OpenCV + NumPy 기준, GPU 경로는 CuPy/CV-CUDA 대안 병기
   - 증강: Albumentations (마스크 동시 변환 필수)
   - 12bit 데이터 손실 없이 다루는 dtype 처리 명시
   - 각 단계 실행 시간 측정(profiling) 코드 포함

[제약 조건]
- 전처리 + 추론 + 후처리 총합 50ms 이내, 택트 100ms.
- 서버급 GPU 1대 기준(구체 모델 미정 → A6000급 가정하고 산정해줘).
- 미검 0% 최우선, 과검 2% 이하.
- 12bit 정보를 임의로 8bit로 떨어뜨리지 말 것.
- 원본 해상도 유지 전제. 만약 리사이즈가 불가피하다면 그 근거를 별도로 제시.
