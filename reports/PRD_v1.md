## 1. 문제 정의 (Problem Statement)

### 1.1 현재 존재하는 문제

- **불량 유출**: 육안 전수 검사에도 불구하고 고객사 입고 검사에서 평균 **1,800 DPPM** 수준의 불량이 검출되고 있다. 월 2~3건의 고객 클레임이 발생하며, 이 중 스크래치(미세 선상 결함)와 부품 누락이 전체 클레임의 78%를 차지한다.
- **검사 편차**: 검사원 개인·시간대별로 판정 기준이 달라 동일 제품이 A조에서는 양품, B조에서는 불량으로 판정된다. 사내 크로스 체크 결과 검사원 간 판정 일치율은 **약 82%**, 야간 조 후반 3시간의 검출률은 주간 대비 **11%p 낮다**.
- **과검(Over-kill) 손실**: 클레임 방지를 위해 검사 기준을 보수적으로 운영한 결과, 배출된 불량품 중 재판정 시 양품으로 판명되는 비율이 **약 30%**다. 월 약 90 EA가 불필요하게 폐기·재작업된다.
- **검사 공정 병목**: 육안 검사 실측 소요 시간이 평균 2.6초로 라인 택트(2.0초)를 초과하여, 검사 구간에서 상시 대기가 발생하고 라인 전체 가동률을 약 4% 잠식한다.
- **원인 추적 불가**: 불량 발생 시 이미지·시각 근거가 남지 않아 어느 설비·어느 시점에서 문제가 발생했는지 특정할 수 없다. 공정 개선이 경험과 추정에 의존한다.

### 1.2 기존 방식의 한계

| 기존 방식 | 한계 |
|---|---|
| 육안 검사 | 피로 누적에 따른 검출률 저하, 판정 기준 불일치, 인력 확보 난이도 상승, 검사 이력 데이터 미확보 |
| 룰 기반 머신비전 (기존 AOI) | 임계값(밝기·면적·에지 강도) 기반이므로 조명 변화·제품 표면 편차·모델 변경에 취약. 곡면 반사체의 미세 스크래치는 배경 텍스처와 구분되지 않아 검출률이 60~70%에 머문다. 신규 결함 유형 추가 시 룰 재설계에 2~4주가 소요된다. |
| 샘플링 검사(AQL) | 전수 보증이 불가능하여 로트 단위 유출 리스크가 남는다 |
| 후공정/출하 검사 | 결함을 늦게 발견하므로 이미 투입된 후공정 가공비·조립 부품비가 전량 손실된다 |

### 1.3 제품이 해결하려는 핵심 가치

1. **불량 유출 차단**: 전수 검사 기준 미검출 유출을 **50 DPPM 이하**로 억제하여 고객 클레임과 반품 비용을 제거한다.
2. **판정 기준의 일관성**: 사람의 상태와 무관하게 24시간 동일한 기준으로 판정한다. 판정 기준은 모델 버전으로 관리되어 추적 가능하다.
3. **과검 손실 최소화**: 과검율을 1.0% 이하로 유지해 양품 폐기 손실을 줄인다.
4. **검사 인력의 고부가 업무 전환**: 전수 육안 검사 인력을 재판정·공정 개선·설비 관리 업무로 재배치한다.
5. **불량 데이터 자산화**: 모든 판정 결과와 결함 이미지를 시계열로 축적하여, 결함 유형별 발생 추이와 설비 상관관계를 분석 가능한 형태로 남긴다.

### 1.4 왜 AI가 필요한가

- **결함의 정의가 규칙으로 기술되지 않는다**: 스크래치는 길이·폭·깊이·방향·조명 각도에 따라 픽셀 패턴이 연속적으로 변화한다. "밝기 차 20 이상, 길이 3px 이상"과 같은 임계값으로는 허용 가능한 표면 텍스처와 불량 스크래치를 분리할 수 없다. CNN 기반 세그멘테이션은 국소 패턴이 아닌 문맥(주변 텍스처 대비 이질성)을 학습하므로 이 구분이 가능하다.
- **미학습 결함에 대한 대응이 필요하다**: 양산 중 새로운 결함 유형이 지속 발생한다. 정상 데이터만으로 학습하는 이상 탐지(Anomaly Detection) 모델은 "정상이 아닌 것"을 잡아내므로, 사전에 정의되지 않은 결함도 검출 후보로 분류할 수 있다.
- **다품종 대응 비용이 다르다**: 룰 기반은 모델마다 룰셋을 새로 설계해야 하지만, 학습 기반은 신규 모델 이미지 300~500장 추가 학습으로 대응 가능하다.
- **판정 신뢰도(Confidence)를 정량 출력한다**: 확률 값을 근거로 "확정 불량 / 재판정 필요 / 양품" 3단 분기를 설계할 수 있어, 과검과 미검출 사이의 트레이드오프를 운영 파라미터로 조정할 수 있다.

> AI가 필요하지 않은 영역은 명확히 분리한다. 치수 측정, 바코드/2D 코드 판독, 부품 유/무의 명확한 존재 판정 같은 결정론적 과제는 기존 룰 기반 비전 라이브러리로 처리하는 것이 정확도·속도·유지보수 측면에서 우월하다. 본 제품은 **룰 기반과 딥러닝의 하이브리드** 구조를 채택한다.

## 2. 사용자 시나리오 (User Scenario)

### 사용자 정의

| 역할 | 설명 |
|---|---|
| 설비 엔지니어 | 시스템 설치·조명 세팅·PLC 연동·모델 전환 레시피 관리 |
| 품질 검사원 (운영자) | 실시간 판정 모니터링, 배출품 재판정, 오판정 피드백 라벨링 |
| 품질 관리자 | 불량률 추이 분석, 기준 승인, 리포트 확인 |
| AI 운영 담당자 | 모델 성능 모니터링, 재학습 트리거, 모델 배포 승인 |

### 2.1 단계별 시나리오

**[1단계] 사용자가 제품을 설치한다**

- 설비 엔지니어가 컨베이어 검사 스테이션에 카메라 3대(상면 1대, 측면 2대)와 조명 유닛(돔 조명 + 로우앵글 다크필드 조명)을 프레임에 장착하고, 차광 인클로저를 씌운다.
- 제품 진입을 감지하는 포토 센서와 컨베이어 위치 추적용 로터리 엔코더를 PLC에 배선한다.
- Edge AI 장비(Jetson Orin NX)를 제어반에 설치하고, 카메라를 GigE(PoE)로, PLC를 PROFINET/OPC UA로 연결한다.
- 배출 스테이션(에어 실린더 푸셔 + 불량품 슈트 + 배출 확인 센서)을 검사 위치로부터 하류 800mm 지점에 설치한다.
- 티칭 모드로 진입하여 모델별로 (a) 조명 세기·노출 시간, (b) 검사 ROI(관심 영역), (c) 판정 임계값을 설정하고 **모델 레시피**로 저장한다. 초기 학습을 위해 모델당 양품 이미지 500장, 결함 이미지 100장 이상을 수집한다. *(가정: 초기 데이터 수집 및 검증에 약 3주)*
- 설치 검증: Gage R&R 및 알려진 불량 샘플 50종을 이용한 검출 시험을 통과해야 양산 승인된다.

**[2단계] AI가 데이터를 수집한다**

- 포토 센서가 제품 진입을 감지하면 PLC가 하드웨어 트리거 신호를 카메라 3대에 동시 전송한다. 엔코더 값으로 제품의 절대 위치와 고유 ID(트래킹 ID)를 부여한다.
- 카메라가 5MP 글로벌 셔터로 노출 시간 200μs 이내 촬상하여 모션 블러를 억제한다. 스크래치 검출용 측면 카메라는 다크필드 조명 조건에서 별도 촬상한다.
- 촬상된 3장의 이미지는 GigE Vision으로 Edge 장비의 링 버퍼에 전송된다. 이미지는 트래킹 ID·타임스탬프·모델 코드·라인 정보와 함께 하나의 검사 트랜잭션으로 묶인다.

**[3단계] AI가 분석을 수행한다**

Edge 장비에서 3단 파이프라인이 순차 실행된다. (TensorRT INT8 최적화 기준 목표 총 지연 120ms 이내)

| 단계 | 처리 | 사용 모델/기법 | 목표 지연 |
|---|---|---|---|
| 전처리 | ROI 크롭, 왜곡 보정, 정합(alignment), 명암 정규화 | OpenCV / 룰 기반 | 15ms |
| 3-1. 부품 누락 검사 | 정합된 ROI별 부품 존재 여부 및 종류 분류 | 템플릿 매칭 + 경량 분류기(ResNet-18) | 20ms |
| 3-2. 표면 결함 검출 | 스크래치·찍힘·이물·오염의 위치와 픽셀 영역 검출 | YOLOv11-seg (인스턴스 세그멘테이션) | 45ms |
| 3-3. 미학습 이상 탐지 | 정상 분포 대비 이질 영역 스코어링 (신규 결함 후보) | PatchCore (양품 only 학습) | 30ms |
| 후처리 | 결함 면적·길이 산출, 규격 대조, 클래스별 임계값 적용 | 룰 기반 | 10ms |

- 결함의 최종 심각도는 AI 검출 결과에 **물리 규격 룰**을 결합해 결정한다. 예: 스크래치 길이 ≥ 1.5mm 또는 폭 ≥ 0.15mm는 Critical, 지정 A면 외부의 길이 0.8mm 미만은 Minor로 분류한다. 픽셀-실치수 변환 계수는 캘리브레이션 타깃으로 산출한다.

**[4단계] 판단 결과를 생성한다**

3단 판정 로직으로 출력한다.

| 판정 | 조건 (가정 기준값) | 후속 처리 |
|---|---|---|
| OK (양품) | 모든 검사 항목 통과, 최대 결함 스코어 < 0.35 | 라인 통과 |
| NG (불량) | Critical 결함 검출 또는 스코어 ≥ 0.70 | 자동 배출 |
| REVIEW (재판정) | 스코어 0.35~0.70, 또는 이상 탐지만 단독 발생 | 배출 후 재판정 트레이로 분리, 운영자 확인 필요 |

- 출력 데이터 구조: `{트래킹 ID, 타임스탬프, 라인/설비 ID, 모델 코드, 판정, 결함 클래스 배열, 결함별 좌표·면적·신뢰도, 모델 버전, 처리 지연}`
- 결함 위치가 오버레이된 이미지와 원본 이미지를 함께 저장한다.

**[5단계] 제품이 사용자 또는 주변 장치를 제어한다**

- Edge 장비가 판정 결과를 **OPC UA / PROFINET**으로 PLC에 전송한다. 전송 페이로드는 트래킹 ID와 판정 코드이며, PLC가 최종 액추에이터 제어 주체다. *(안전 및 결정론적 타이밍 보장을 위해 액추에이터 직접 제어는 Edge가 아닌 PLC가 담당한다.)*
- PLC는 엔코더 기반으로 해당 트래킹 ID의 제품이 배출 스테이션에 도달하는 시점을 계산하여 에어 실린더를 작동시킨다. 판정 시점부터 배출 완료까지 목표 500ms 이내.
- 배출 확인 센서가 슈트 통과를 감지하지 못하면 **배출 실패 인터록**을 발생시켜 컨베이어를 정지하고 타워램프(적색) + 부저를 작동시킨다.
- 동시에 알림 시스템이 작동한다.
  - 연속 3개 이상 동일 클래스 NG 발생 → 설비 담당자에게 즉시 알림(사내 메신저 웹훅 + 타워램프 황색)
  - 10분 이동 불량률이 관리 상한(3σ) 초과 → 품질 관리자 알림
  - REVIEW 대기 건수 20건 초과 → 검사원 알림
  - Edge 장비 온도·추론 지연·카메라 연결 이상 → 시스템 담당자 알림

**[6단계] 사용자가 결과를 확인하고 후속 행동을 수행한다**

- 검사원은 라인 옆 터미널에서 배출된 제품의 결함 오버레이 이미지를 확인하고, 실물과 대조해 **최종 확정(불량 확정 / 양품 오판정)** 을 입력한다. 이 입력은 그대로 재학습용 라벨이 된다.
- 오판정 입력이 누적되면 대시보드에 모델 성능 저하 경고가 표시되고, 주간 단위로 재학습 후보 데이터셋이 자동 구성된다.
- 품질 관리자는 대시보드에서 결함 클래스별 파레토 차트, 시간대·설비·모델별 불량률 추이, 검사 이력을 조회하고 주간 품질 리포트를 출력한다.
- AI 운영 담당자는 재학습된 모델을 **섀도 모드**(판정에 영향 없이 병렬 추론)로 3일간 검증한 뒤, 성능 지표 충족 시 정식 배포한다. 배포 후 성능 저하가 확인되면 이전 버전으로 즉시 롤백한다.

## 3. 성공 지표 (Success Metrics)

### 3.1 핵심 KPI (검사 정확도)

| 지표 | 정의 | 목표 | 측정 방법 |
|---|---|---|---|
| Critical 결함 검출률 (Recall) | 실제 Critical 불량 중 검출된 비율 | **≥ 99.5%** | 알려진 불량 샘플 200종 주간 시험 + 배출품 100% 재판정 |
| 전체 결함 검출률 | Minor 포함 전체 결함 검출률 | ≥ 97.0% | 동일 |
| 미검출 유출률 | 통과품 중 실제 불량 비율 | **≤ 50 DPPM** | 통과품 일 500 EA 샘플링 재검 + 고객 입고 검사 결과 |
| 과검율 (False Positive Rate) | 양품을 NG로 판정한 비율 | **≤ 1.0%** | 배출품 재판정 결과 |
| 정밀도 (Precision) | NG 판정 중 실제 불량 비율 | ≥ 90% | 배출품 재판정 결과 |
| REVIEW 발생률 | 전체 검사 중 재판정 분기 비율 | ≤ 2.0% | 시스템 로그 |

## 5. 개발 범위 / 비범위 (Scope)

### 5.1 개발 범위 (In Scope)

1. **실시간 다중 카메라 촬상 및 동기화**: 하드웨어 트리거 기반 3채널 동시 촬상, 조명 스트로브 동기, 엔코더 기반 제품 개체 트래킹 ID 부여.
2. **AI 결함 검출 엔진**: 표면 결함 세그멘테이션(스크래치·찍힘·이물·오염), 부품 누락 검사, 미학습 이상 탐지의 3단 하이브리드 파이프라인 및 TensorRT 최적화.
3. **결함 심각도 판정 로직**: 픽셀-실치수 변환, 결함 면적·길이 산출, 검사면(A/B면)별 차등 기준 적용, OK/NG/REVIEW 3단 분기.
4. **PLC 연동 및 자동 배출 제어**: OPC UA 판정 결과 전송, 엔코더 기반 배출 타이밍 계산, 에어 푸셔 제어, 배출 확인 센서 피드백, 배출 실패 시 라인 정지 인터록.
5. **모델 전환 레시피 관리**: 5개 제품 모델별 조명·노출·ROI·임계값·AI 모델 프로파일을 레시피로 저장/전환, MES 모델 코드 수신 시 자동 전환.
6. **데이터 저장 및 이력 관리**: 판정 결과 DB 적재, 원본/오버레이 이미지 오브젝트 스토리지 저장, 보존 정책에 따른 자동 아카이빙·삭제, 로트 단위 추적성 확보.
7. **관리자 웹 페이지**: 실시간 판정 스트림, 판정 이력 검색/필터, 결함 이미지 오버레이 뷰어, 임계값 설정, 레시피 관리, 사용자별 화면.
8. **재판정 및 피드백 라벨링 워크플로**: 검사원의 최종 확정 입력 UI, 오판정 데이터 자동 수집, 재학습 후보 데이터셋 자동 구성.
9. **알림 기능**: 타워램프·부저 제어, 연속 불량·불량률 관리 이탈·REVIEW 적체·장비 이상에 대한 룰 기반 알림, 메신저 웹훅 및 이메일 발송.
10. **모니터링 대시보드**: 결함 클래스별 파레토, 시간대·설비·모델별 불량률 추이, 처리 지연·가동률·장비 온도 등 시스템 헬스 지표.
11. **로그 및 감사 추적**: 판정 로그, 시스템 이벤트 로그, 설정 변경 이력(변경자·시각·변경 전후 값), 모델 버전-판정 결과 매핑 기록.
12. **모델 재학습 및 배포 파이프라인**: 라벨링 → 학습 → 성능 평가 → 섀도 모드 검증 → 배포 → 롤백의 반자동 파이프라인 (학습 실행은 담당자 승인 기반).
13. **MES 연동 인터페이스**: 모델 코드/로트 정보 수신, 판정 결과 및 품질 성적서 송신.
14. **설치 및 검증 절차**: 캘리브레이션 도구, 알려진 불량 샘플 기반 자동 검증 테스트, Gage R&R 리포트 생성 기능.

### 5.2 개발 제외 범위 (Out of Scope)

1. **음성 인식 및 음성 명령 인터페이스** — 소음 환경(80dB 이상)에서 인식률이 확보되지 않고, 조작 빈도가 낮아 투자 대비 효용이 없다.
2. **모바일 애플리케이션(네이티브 iOS/Android) 개발** — 알림은 기존 사내 메신저 웹훅으로 대체하고, 조회는 모바일 반응형 웹으로 최소 대응한다.
3. **다국어 지원(i18n)** — 1차 도입 라인은 국내 단일 사업장이므로 한국어 UI만 제공한다. 해외 라인 확산 시 Phase 3에서 검토한다.
4. **클라우드 기반 학습 및 클라우드 추론** — 이미지 데이터의 사외 반출 통제 정책과 전송 비용/지연 문제로, 학습과 추론 모두 온프레미스로 한정한다.
5. **세분화된 사용자 권한 관리(RBAC) 및 SSO 연동** — 1차 버전은 운영자/관리자 2단계 계정만 제공한다. 부서·기능별 세분화 권한 체계는 Phase 2로 이관한다.
6. **불량 원인 자동 진단(Root Cause Analysis) 및 설비 파라미터 자동 보정** — 결함과 설비 파라미터 간 인과 추론은 별도 데이터 축적(최소 6개월)이 선행되어야 하며, 설비 자동 제어는 안전 검토가 추가로 필요하다. 본 버전은 상관 데이터 제공까지만 담당한다.
7. **불량품의 자동 재작업(Rework) 및 자동 분류 로봇 핸들링** — 배출까지만 자동화하고, 배출 이후 재작업·폐기 분류는 기존 수작업 프로세스를 유지한다.
8. **치수 정밀 측정 및 3D 형상 검사** — 본 버전은 2D 외관 검사에 한정한다. 단차·변형 등 3D 결함 대응은 3D 센서 추가 도입과 함께 Phase 3에서 검토한다.
9. **X-ray, 초음파 등 비파괴 내부 결함 검사** — 검사 원리와 안전 규제가 상이하여 별도 제품으로 분리한다.
10. **타사 설비 범용 호환 드라이버 개발** — 지정 카메라 3종·PLC 2종(Siemens/Mitsubishi)에 한정 지원한다.
11. **다중 사업장 통합 관제 시스템** — 1개 라인 단위 시스템으로 개발하고, 전사 통합 관제는 라인 3개 이상 확산 후 별도 프로젝트로 진행한다.

### 6.6 정성적 편익 (수치화 제외)

- 고객사 품질 감사 대응력 향상: 전수 검사 이력과 이미지 근거를 즉시 제시 가능. 신규 수주 심사에서의 정성 평가 개선.
- 품질 데이터 자산 축적: 결함 이미지·시계열 데이터가 향후 원인 분석·설비 예측 정비 프로젝트의 기반 자산이 된다.
- 인력 리스크 완화: 검사 인력 채용난과 숙련도 편차에 대한 구조적 의존을 제거한다.
- 확산 시 한계 비용 감소: 2호 라인 이후에는 모델 개발비·SW 개발비(합 95,000,000원)의 대부분이 재사용되어 라인당 CAPEX가 약 40% 수준으로 하락한다.

### 6.7 최종 판정

**판정: 투자 승인 권고 (Approve)**

| 판단 기준 | 사내 기준 (가정) | 실적 | 충족 |
|---|---|---|---|
| 투자 회수기간 | 18개월 이내 | 5.2개월 (보수 시나리오 8.1개월) | 충족 |
| 연간 ROI | 50% 이상 | 231.0% (최악 시나리오에서도 80.9%) | 충족 |
| 전략 적합성 | 품질 경쟁력 및 자동화 로드맵 부합 | 부합 | 충족 |

**판정 근거**

1. 기준 시나리오에서 회수기간 5.2개월로 사내 투자 기준(18개월)을 크게 하회하며, 절감 효과가 절반만 실현되고 운영비가 30% 초과하는 최악 시나리오에서도 회수기간 14.8개월로 기준을 충족한다. 즉 **재무적 하방 리스크가 제한적**이다.
2. 절감액의 최대 항목이 인건비(37%)와 클레임 비용(29%)에 분산되어 있어, 한 항목이 미실현되더라도 사업성이 붕괴하지 않는다.
3. 2호 라인 이후 CAPEX가 약 40% 수준으로 하락하므로, 확산을 전제하면 전사 ROI는 기준 시나리오를 상회할 가능성이 높다.

**승인 조건 (Conditions)**

- Phase 0 PoC에서 오프라인 검출률 95% 미달 시 광학 설계를 재검토하고, 재검토 후에도 미달이면 투자를 중단한다. (전체 CAPEX의 약 5%인 PoC 단계에서 최대 리스크를 차단한다.)
- Phase 2 병행 운영에서 **Critical 검출률 99.5% 및 과검율 1.0%** 를 충족하기 전에는 자동 배출을 활성화하지 않는다.
- 인력 4명 감축은 인위적 감원이 아닌 **타 공정 재배치**를 전제하며, 재배치 계획을 Phase 1 종료 시점까지 인사 부서와 확정한다. 재배치가 불가할 경우 인건비 절감분은 ROI 산정에서 제외하고 재승인 절차를 밟는다.
